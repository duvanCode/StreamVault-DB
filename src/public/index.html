Configuración de Google Drive

Credenciales para la subida por streaming directo hacia la nube.

¿Qué método de autenticación debes elegir?

Opción 1: OAuth 2.0 (Cuentas @gmail.com)

Si usas una cuenta de Gmail personal, este es el método requerido. Las copias se suben directamente a tu almacenamiento personal (15 GB gratuitos o Google One). Solo requiere Client ID y Secret.

Opción 2: Cuenta de Servicio (Google Workspace)

Google asigna 0 GB de cuota a las Cuentas de Servicio. Para usarlas sin error de cuota, la carpeta debe estar dentro de una Unidad Compartida (Shared Drive) de Workspace.

El ID que aparece al final de la URL en drive.google.com/drive/folders/ID (o 'root' para la raíz)

Conectar con Google OAuth 2.0

Ingresa tu Client ID y Secret de Google Cloud y haz clic en Conectar para autorizar en 1 clic.

Copia y pega esta URL en Google Cloud Console > APIs y servicios > Credenciales > Tu ID de cliente OAuth > URIs de redireccionamiento autorizados.
Sin Token
⚠️ Aviso importante: Para usar Cuenta de Servicio, la carpeta DEBE pertenecer a una "Unidad Compartida" (Shared Drive) de Google Workspace y debes invitar a tu client_email como Gestor de contenido. En cuentas personales @gmail.com Google bloquea la subida con error de cuota cero.

¿Cómo funciona el streaming directo a Google Drive?

Al ejecutarse la copia, el comando pg_dump o mysqldump escribe en la salida estándar (stdout), pasando inmediatamente por un compresor gzip en memoria y transmitiéndose por fragmentos HTTP directo al API de Google Drive. En ningún momento se guarda el archivo en el disco duro del VPS, evitando que se agote el espacio de almacenamiento.

Despliegue en VPS con Dokploy

Instrucciones y configuración para subir este servicio directamente a tu servidor.

Dokploy Compatible

Paso 1: Configurar en Dokploy

1. En tu panel de Dokploy, crea un nuevo Proyecto y añade una Aplicación.
2. Conecta tu repositorio de GitHub / Git o selecciona Dockerfile.
3. Dokploy detectará automáticamente el archivo Dockerfile optimizado que incluye postgresql-client, mysql-client y node:22-alpine.
4. En la casilla Port de la aplicación en Dokploy, coloca el mismo puerto definido en la variable PORT (por defecto 3000, o cualquier puerto que desees como 8080, 5000, etc.).

Paso 2: Montar Volumen Persistente

Para que las configuraciones de bases de datos y el historial no se borren al reiniciar el contenedor, añade este volumen en Dokploy:
• Host Path / Volume: job_db_data
• Mount Path: /app/data

Paso 3: Variables de Entorno (.env)

Configura las variables en la pestaña Environment de Dokploy:

PORT=3000 # O el puerto que elijas para Dokploy (ej: 8080, 5000) BACKUP_CRON=0 2 * * * TIMEZONE=America/Bogota DASHBOARD_PASSWORD=tu_clave_secreta # Opcional (si deseas precargar las credenciales sin usar la web): DEFAULT_DB_TYPE=postgres DEFAULT_DB_HOST=172.17.0.1 DEFAULT_DB_PORT=5432 DEFAULT_DB_NAME=mi_base_de_datos DEFAULT_DB_USER=postgres DEFAULT_DB_PASSWORD=mi_password GOOGLE_DRIVE_FOLDER_ID=1A2b3C4d5E... GOOGLE_SERVICE_ACCOUNT_KEY='{"type":"service_account",...}'
